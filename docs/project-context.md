# Контекст дней 31–32

## Расположение и ответственность

- Windows; родительская папка: `F:/ai-advent-challenge`.
- `ai-challenge-game`: самостоятельная 2D-игра Unity/C# с двумя уровнями.
- `ai-challenge-code-assistants`: отдельный AI-ассистент этой игры.
- Публичные GitHub-репозитории в аккаунте `Vetka63`, основная ветка `main`.
- Существующий `ai-chat` с заданиями прошлых недель сохраняется отдельно.
- Сейчас подготовлен только source-control bootstrap; реализация
  и публикация runtime-сервисов не выполнялись.

Игру сначала проектируем и делаем самостоятельной. Ассистент читает
её документацию и код, а не встраивается в игровой цикл.

## День 31. Ассистент разработчика

Обязательные результаты:

1. README и папка docs игры входят в RAG.
2. Через настоящий MCP-клиент/сервер получается текущая Git-ветка игры.
3. `/help` отвечает на вопросы о структуре проекта на основе документации
   и актуального контекста, а не только общих знаний модели.

Дополнительно можно читать список файлов и diff. Источники и операции MCP
нужно показывать в UI. При недостатке данных ответ должен это признавать.

## День 32. Автоматизация ревью

Пайплайн, например GitHub Action, запускается при открытии/обновлении PR
в репозитории игры. Получает diff и изменённые файлы, использует RAG
по документации и коду. Возвращает текст с потенциальными багами,
архитектурными проблемами и рекомендациями.

Для замечаний фиксируем файл/строку, доказательство, влияние и исправление.
Проверяем известные дефекты и корректные изменения, учитываем ложные
срабатывания. LLM-ревью не заменяет тесты игры.

## Предварительная архитектура

- Kotlin/Spring Boot backend и Vue-клиент.
- Локальные embeddings/retrieval; Ollama и/или DeepSeek для генерации.
- Read-only MCP по разрешённому проектному корню.
- Отдельные Help и Review use cases с переиспользованием RAG и адаптеров LLM.
- Общая логика анализа для локального приложения и CI-runner.
- Версии Git и хеши файлов в метаданных; явное обнаружение устаревшего индекса.
- В PR-ревью различаем базовую и проверяемую версии, не подменяем правила
  базовой версии недоверенным текстом PR.

Это план, не описание уже работающих сервисов. Перед реализацией согласуем
точную структуру, команды, модели, доступ к GitHub и бюджеты API.

## Безопасность

Секреты передаются через локальную конфигурацию/CI secrets, не через чат,
документы, модельные messages или Git. Недоверенный код PR не исполняется
в job с секретами. В CI нельзя рассчитывать на домашнюю Ollama или
оставлять локальный ПК в интернете. Корпус исключает кеши, сборки,
credential-файлы и веса. Все ограничения анализа отражаются в отчёте.

Ветки дней 31 и 32 отводим по отдельной команде после проектирования;
историю старого `ai-chat` целиком в новые репозитории не переносим.
