# План разработки ассистентов для дней 31–34

План согласован 16 октября 2026 года. Игра развивается независимо в соседнем
репозитории. Здесь последовательно добавляются четыре домена с общими RAG,
адаптерами LLM, MCP-клиентом и хранением результатов.

## Архитектура и границы

Backend — Kotlin/Spring Boot, frontend — Vue/TypeScript, хранилище — SQLite.
Embeddings и поиск локальные; генерация через DeepSeek или Ollama без скрытого
переключения провайдера. У каждого домена собственные DTO, политики, тесты
и описание рядом с кодом. Общая инфраструктура не выдаёт всем агентам общие
права и не превращает их инструкции в один большой системный промпт.

Project MCP только читает разрешённые документы, исходники и Git-контекст.
В будущем Support MCP читает учебные JSON-тикеты, Workspace MCP работает
с изолированной копией. Произвольный shell, секреты и изменения игры
не предоставляются помощнику разработчика.

Индекс сохраняет точный текст, путь, раздел, строки, хеш документа, Git SHA
и identity embedding-модели. Исследования, история и актуальная реализация
различаются. Будущий двухчасовой вариант не становится реализованной механикой
из-за упоминания в исследовании; текущая длительность берётся из актуальных документов.

## День 31

Ветка ai-challenge-day-31 от подготовленного main.

1. Каркас приложения, локальная конфигурация, история и журнал MCP.
2. RAG по README и docs игры с метаданными происхождения.
3. Настоящие MCP initialize, tools/list и tools/call для Git-контекста,
   чтения, поиска и получения снимка документов.
4. /help: текущий контекст через MCP, retrieval, ответ LLM со ссылками.
5. UI показывает источники, ветку/SHA, устаревание индекса, ошибки и сохранённые ответы.
6. Автотесты, реальные запросы и пошаговый гайд для видео.

Приёмка: структура проекта; связь ECS/Zenject; актуальные правила боссов;
отличие текущей сборки от предложения; неизвестный факт; недоступный MCP;
изменение источников; повторное открытие результата после перезапуска.

## День 32

Ветка ai-challenge-day-32 от завершённого дня 31.

Уточнение пользователя: Actions только создаёт JSON-задание, локальный
backend забирает его polling-ом каждые 30 секунд и выполняет RAG/генерацию.
CLI-анализатор на GitHub runner, self-hosted runner и туннель не нужны.
Добавляются индексирование C#, diff и изменённые файлы PR, Review-домен,
durable очередь SQLite, GitHub-адаптер, UI и workflow без DeepSeek-ключа.
Не запускать недоверенный код с секретами. Отчёт связывается с base/head
SHA и содержит баги, архитектурные проблемы, рекомендации, пути, строки,
основания и ограничения покрытия. Детали: day32-architecture.md.

Проверить известный дефект, архитектурное нарушение, корректный PR,
обновление PR, ошибки API и неполный diff. LLM-ревью не заменяет тесты.

## День 33

Ветка ai-challenge-day-33 от завершённого дня 32.

Отдельный Support-домен и пользовательский корпус FAQ/управления/ограничений.
JSON с вымышленными пользователями и тикетами доступен через Support MCP.
Тикеты не включаются в общий индекс. Backend проверяет доступ к обращению.
UI показывает ответ, источники, версию сборки и использованный контекст.

Проверить FAQ, персонализированный ответ по тикету, продолжение,
недостаток данных и отказ в доступе к чужому обращению.

## День 34

Ветка ai-challenge-day-34 от завершённого дня 33.

Workspace-домен получает цель, самостоятельно ищет и читает 2–3 файла,
анализирует их и сохраняет результат как diff или новый документ.
Обязательные сценарии:

1. Проверить документацию управления по текущему коду и подготовить исправления.
2. Найти использования ArenaSettings и создать отчёт о влиянии изменений.

Работа только в отдельной копии/worktree игры. Минимальный результат —
сохранённый diff. Применение отдельной итерацией после подтверждения
конкретного patch; проверяются исходные хеши и конфликты. Сначала разрешены
только согласованные текстовые документы. Сцены, префабы, бинарные ассеты,
.git, секреты и произвольный shell недоступны. Повторное применение не
создаёт дубликаты. Commit, push и merge не выполняются автоматически.

## Общее завершение каждого дня

Реализация → автоматические проверки → реальные запросы → UI-проверка →
гайд для записи видео. Commit/push/merge — по команде пользователя.
Чаты, ответы, snapshots, индексы и ключи не публикуются в Git.
