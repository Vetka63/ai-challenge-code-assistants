# Проверка дня 35 и запись видео

## Что решает приложение

AI автоматически составляет паспорт реальной Unity-игры: что это за игра,
какие механики описаны, какие есть сцены/режимы, что изменилось и где это
подтверждено. Человек не пересказывает всю документацию при каждом изменении.
Игра не запускается и не изменяется; изображения показываются без vision-анализа.

## Запуск на этой машине

Откройте Docker Desktop. Из папки рабочей копии дня 35 запустите:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Day35.ps1
```

Для пересборки добавьте `-Build`. Скрипт принимает GamePath, ExistingKeyFile
и OllamaContainer, если расположение игры/установленного Ollama другое.
Существующий ключ читается только в процесс запуска; в Git не сохраняется.

UI: http://localhost:8983/#passport. API: http://127.0.0.1:8982.
Проверка не требует открытого браузера, но Docker/ПК должны работать.
Выключенный/спящий ПК не является сервером 24/7.

## Короткий сценарий для сдачи

1. Откройте «Паспорт игры · день 35». Вверху видна реальная задача и цепочка
   «Документация и код → MCP → AI → новая версия».
2. Выберите DeepSeek Pro или локальную модель. Интервал оставьте 10 минут.
   Установите разумную квоту генераций в сутки. Нажмите «Сохранить настройки».
   Модель и квота не меняются от одного переключения ещё не сохранённой формы.
3. Нажмите «Проверить сейчас». Появятся сбор источников, затем вызов модели.
   Если готовый паспорт уже есть и файлы не менялись, сразу будет «Без изменений».
   Для записи нового AI-вызова есть отдельная кнопка подтверждённой генерации.
4. Покажите готовую версию: дату, snapshot/hash, обзор и механики.
   Под каждым утверждением указаны его тип и ссылки S1…Sn.
5. Покажите карточки сцен, режимов и планов. Arena из build settings не
   выдаётся за два пройденных уровня. Состав зависит от текущей игры и источников.
6. Откройте источник по S-ID. В UI видны настоящий путь, номера строк,
   SHA-256 и тот фрагмент, который получила модель.
7. Покажите галерею и предупреждение о дате импорта/версии сборки.
8. Раскройте «Алгоритм и журнал проверки»: collector REST, MCP initialize,
   tools/list, read_file, модель и время. Это показывает участие AI в процессе.
9. Нажмите «Проверить сейчас» ещё раз без изменений исходников. Новая строка
   журнала — «Без изменений · без LLM», счётчик генераций не растёт.
10. Включите «Проверять автоматически», выберите явно помеченный демо-интервал
    30 секунд и сохраните настройки. Покажите время следующего запуска.
    Примерно через 30–35 секунд появится запись «По расписанию» без нажатия кнопки.
    Если исходники прежние, это корректный пропуск LLM, а не ошибка автоматики.
11. Откройте историческую успешную версию и нажмите «К текущему паспорту».
    Скачайте MD: это экспорт существующей версии, не новый вызов модели.
12. Верните 10 минут и сохраните настройки. Наблюдение можно оставить включённым
    или остановить кнопкой «Пауза наблюдения». Уже отправленный запрос не отменяется.

## Как показать появление новой версии

Основная игра разрабатывается параллельно. Когда её автор сам изменит README,
docs или разрешённый код, следующая проверка увидит новый fingerprint и
сформирует новую версию. Старую можно открыть в истории. Список изменений
покажет добавленные, изменённые и удалённые файлы.

Для искусственной демонстрации используйте отдельную тестовую папку и отдельный
Compose project/volumes/порты, а не редактируйте настоящую игру ради видео.
В контрольном прогоне разработки такой сценарий проверяется отдельно; детали
и фактические результаты фиксируются в day35-verification.md.

## Если появилась ошибка

FAILED не стирает готовый паспорт. Откройте ошибочную проверку: видны код,
журнал и сохранённый ответ модели, если он получен. Ошибка JSON/ссылок не
становится новой успешной версией.

BLOCKED с RETRY_CONFIRMATION означает, что для этих исходников уже была
неудачная или неопределённая попытка. После исправления причины нажмите
«Повторить генерацию с подтверждением…». Это может быть новый платный вызов.
Дневной лимит действует и на повтор. После timeout нельзя гарантировать,
что провайдер не списал токены: поэтому такие попытки учитываются в квоте.

При потере подтверждения отправки кнопка повторяет прежний UUID, не создаёт
новое намерение. При перезапуске приложение сохраняет версии/настройки и
не повторяет неопределённый LLM-вызов автоматически.

## Остановка без удаления данных

```powershell
docker compose -f compose.day35.yml stop
```

Не используйте `down -v`, если нужна история. Общая Ollama остаётся отдельным
контейнером и не останавливается этой командой.
