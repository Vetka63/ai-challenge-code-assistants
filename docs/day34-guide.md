# Проверка файлового ассистента дня 34

Для сдачи покажите два сценария: проверку документации управления и отчёт
об использовании ArenaSettings. В обоих случаях задаётся цель, а файлы выбирает агент.
Документ или diff сохраняется отдельно от основной игры.

## Запуск

Рабочая папка PowerShell:
F:\ai-advent-challenge\ai-challenge-code-assistants

Запуск с существующим локальным ключом без вывода секрета:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Day34.ps1 -Build -KeyFile F:\ai-advent-challenge\ai-chat\.env -KeyVariable LLM_API_KEY

Без KeyFile доступны локальные запросы при наличии модели в Ollama.
Основная игра смонтирована только для чтения. Ревью дня 32 остаётся выключенным.
Не используйте down -v: это удалит runtime-данные.

## Подготовка в браузере

1. Откройте http://localhost:8683/#workspace. После обновления сборки перезагрузите страницу.
2. Нажмите «Создать свежий снимок».
3. Убедитесь, что появился снимок с датой, числом файлов и fingerprint.
4. Выберите DeepSeek или Ollama. Облако должно быть явно выбрано.
5. В снимок не подмешиваются последующие изменения игры. Для новой версии создайте новый снимок.

## Сценарий проверки документации

Нажмите первую подсказку или введите:

> Проверь инструкцию клавиатурного управления ASCII-прототипом первого акта по его коду и подготовь diff её исправления. Исторические описания не переписывай. Если расхождений нет, сохрани отчёт проверки.

1. Нажмите «Поручить агенту».
2. Покажите журнал: модель выбирает поиск и чтение через MCP.
3. Дождитесь завершения и откройте «Прочитано файлов». Должны быть минимум три разных пути.
   Кнопка «Показать прочитанные фрагменты» открывает реальные сохранённые ответы MCP
   с номерами строк. Она не вызывает модель и не перечитывает изменившуюся игру.
4. Откройте сохранённый документ. Проверьте ссылки path:line и объяснение найденных расхождений.
5. Переключите «Документ» на «Diff». Если расхождений нет, допустим новый отчёт проверки вместо выдуманного исправления.
6. Скачайте MD или patch. Это уже сохранённый результат, нового обращения к LLM нет.

Не выдавайте статус COMPLETED за доказательство правильности каждого утверждения.
Сопоставьте несколько конкретных выводов с указанными строками.

## Сценарий анализа компонента

1. Нажмите «Новая задача» и оставьте тот же снимок.
2. Введите:

> Найди использования ArenaSettings и создай документ о том, какие части игры зависят от этих настроек. Приведи пути и строки исходников.

3. Запустите и покажите search_files, затем read_file по разным файлам.
4. Дождитесь сохранённого Markdown-отчёта с зависимостями и основаниями.
5. Покажите минимум три прочитанных файла и инструмент create_document.
6. Перезагрузите страницу: запуск и документ должны остаться.

Уточнение можно отправить с включённым «Продолжить эту задачу».
При FAILED/INTERRUPTED создайте новую задачу на том же снимке: незавершённая
последовательность tool calls не отправляется провайдеру как исправная история.

## Проверка через CLI

CLI — второй интерфейс того же backend. Сначала запустите приложение.
Обёртка использует Docker и не требует установки JDK на Windows.

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Assistant.ps1 help
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Assistant.ps1 snapshots

Скопируйте UUID нужного снимка вместо SNAPSHOT_UUID:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Assistant.ps1 run SNAPSHOT_UUID DEEPSEEK "Найди использования ArenaSettings и создай отчёт о влиянии изменений."

В начале будет Run ID, затем операции и сохранённые артефакты.
Тот же запуск доступен в браузере по #workspace/RUN_UUID.

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Assistant.ps1 show RUN_UUID
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Assistant.ps1 artifacts RUN_UUID
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Assistant.ps1 export RUN_UUID ARTIFACT_UUID patch

Команда export выводит текст в stdout, не применяет patch.
Сохраняйте скачанный patch как исходный файл. При проверке во временной копии
используйте git -c core.autocrlf=false apply --check, чтобы глобальное преобразование
переводов строк Windows не меняло ожидаемый результат.
Для однократной отправки без ожидания используйте --no-wait; для повторной
отправки при потере подтверждения — прежний --id и точно те же параметры.
Не меняйте UUID для проверки идемпотентности: новый UUID запускает новую задачу.
Ctrl+C отключает клиент, но не отменяет backend-запуск.

## Что показать на видео

Создание снимка → цель без списка файлов → самостоятельные MCP-вызовы →
минимум три прочитанных файла → документ и diff → повторное открытие результата.
Повторите для второго сценария. CLI можно показать отдельным коротким фрагментом.
Проверки не требуют изменения основной игры, создания PR или включения дня 32.
