# Архитектура живого паспорта игры

День 35 решает реальную задачу: разработка игры идёт параллельно, и человеку
нужен обзор её текущего устройства, режимов, изменений и иллюстраций без ручного
перечитывания README, документации и кода. AI формирует обзор из сохранённых
источников; сбор, расписание, версии и защита от повторных расходов — обычный код.

## Компоненты и владельцы

| Компонент | Ответственность |
|---|---|
| Vue PassportPanel | Настройки, запуск, история, карточки, источники, галерея, MD |
| PassportController | HTTP-адаптер сценария |
| PassportScheduler | Раз в 5 секунд проверяет, пора ли выполнить сохранённое расписание |
| RefreshPassport | Общий сценарий ручного и фонового обновления |
| PassportRepository | Собственные таблицы SQLite, захват работы и атомарная публикация |
| HttpPassportSources | Внутренний collector API Workspace MCP, фиксированный URL |
| PassportEvidenceReader | Выбор ограниченных фрагментов и настоящие MCP read_file |
| PassportPolicy | Prompt, схема JSON, проверка происхождения ссылок |
| JsonGenerator | Один вызов явно выбранной Ollama или DeepSeek Pro с JSON-mode |
| WorkspaceStore | Неизменяемые снимки исходников, дедупликация по содержимому |
| PassportCollector | Разрешённые PNG/JPEG, сохранение растров по SHA-256 |

Это отдельный домен `passport` существующего backend, а не новый микросервис
со своей копией бизнес-логики. Ресурсоёмкие агенты согласованы общим `Jobs`.
SQLite таблицы `passport_state` и `passport_checks` принадлежат только паспорту.
Общие LLM/MCP-адаптеры переиспользуются; чужие repositories сценарий не импортирует.

## Один цикл обновления

1. Кнопка или scheduler вызывает один и тот же `RefreshPassport.start`.
2. UUID обеспечивает повторяемое получение прежнего задания. Глобальный слот
   резервируется без очереди; активная проверка фиксируется в SQLite.
3. Workspace MCP через внутренний REST собирает разрешённые тексты и media.
   Двойное чтение проверяет стабильность исходников. Снимок неизменяемый;
   повтор того же содержимого получает прежний ID, а не ещё одну полную копию.
4. Сравниваются fingerprint с последней успешной версией и хеши файлов:
   ADDED, MODIFIED, DELETED. Ошибочная попытка не становится базой сравнения.
5. Если содержимое прежнее — `NO_CHANGES`, без MCP-чтений фрагментов и LLM.
   Неопределённая/ошибочная модельная попытка с тем же fingerprint требует
   отдельного подтверждения. Порядок этой защиты важнее пропуска без изменений.
6. Backend выбирает README, точный EditorBuildSettings, актуальные ссылки docs
   из начала README и код прототипа. Research не приоритетный текущий документ.
   Фрагменты реально читаются через официальный MCP SDK, `read_file`;
   серверный hash и номера строк сверяются с неизменяемым снимком.
7. Перед сетевым вызовом сохраняется `attemptedAt`, проверяется суточная квота.
   Prompt содержит только фактически прочитанные фрагменты. Ключ — только
   в HTTP-заголовке провайдера. Пиксели изображений не передаются модели.
   JSON-mode включается на уровне API, не только просьбой в prompt:
   [DeepSeek response_format](https://api-docs.deepseek.com/guides/json_mode/),
   [Ollama format](https://docs.ollama.com/capabilities/structured-outputs).
   Схема и источники дополнительно проверяются приложением. Ожидание этого
   локального JSON-ответа — до 600 секунд; DeepSeek — до 180 секунд.
   Лимит выходных токенов искусственно не задаётся, скрытого повтора нет.
8. Сохраняются raw-ответ, фактическое API usage, модель и время. Затем проверяются
   завершённость, JSON, типы карточек и ссылки на реальные источники S1…Sn.
9. Результат и указатель текущей версии публикуются одной короткой транзакцией.
   В случае ошибки прежний успешный паспорт остаётся доступным.
10. Следующий срок назначается после завершения: +600 секунд, либо +30 секунд
    в явно обозначенном демонстрационном режиме. Пропущенные тики не копятся.

Внутренний REST сбора не выдаётся за MCP tools/call. Настоящие MCP операции
видны в журнале отдельно: initialize, tools/list, read_file. Пять инструментов
дня 34 не меняются; произвольный shell или root в контракт не добавлены.

## Источники и изображения

Тексты: README.md, docs/**/*.md, C# из AsciiArena/Assets/Prototype и только
AsciiArena/ProjectSettings/EditorBuildSettings.asset. Library, сборки, секретные
конфиги и остальные Unity-ассеты не индексируются. Это целевой сбор контекста,
не семантический RAG-индекс и не исполнение Unity-кода.

Для облака выбирается до 46 000 символов фрагментов, для локальной модели —
до 11 000, не более 18 источников. Каждый диапазон — не более 160 строк.
Список выбранных фрагментов сохраняется с версией и выводится в UI/MD.
Ограниченный охват не доказывает отсутствие механики в непрочитанных файлах.

PNG/JPEG принимаются по локальным Markdown-ссылкам в art/playtests и
Assets/Screenshots, дополнительно из Assets/Screenshots. Внешние URL не
скачиваются. До 12 растров, до 8 МБ каждый, до 32 МБ суммарно; ограничиваются
размеры и число пикселей, проверяется настоящий формат. SVG/HTML/GIF не включены.
Ссылки/выход за разрешённый корень не допускаются. Сохранение по хешу означает,
что старая версия продолжает показывать старое изображение после изменения игры.

Дата импорта — дата появления в хранилище ассистента, не дата съёмки.
Галерея не доказывает внешний вид текущей сборки. Связь с документом видна;
автоматической привязки изображения к уровню и vision-анализа в этой версии нет.

## Как читать паспорт

- DOCUMENTED — так написано в источнике.
- CODE_PRESENT — найдено в коде; значения полей могут быть defaults, не runtime.
- REPORTED_TEST — прогон заявлен в отчёте, ассистент его не выполнял.
- PLANNED — целевое направление, не готовая функция.
- SCENE — сцена, а не доказанный отдельный уровень; MODE — игровой режим.

Сервер проверяет структуру и происхождение ссылок, не истинность каждого вывода.
Дополнительно есть целевая защита известного риска нашего README: исходный объём
двух уровней нельзя выдать за реализованные два уровня без подтверждения источником.
Это проверка конкретной неоднозначности, не универсальный семантический judge.
Ранние диагностические версии помечены в UI и не переписываются задним числом.
При противоречиях нужны вопросы/проверка человеком. Старый AI-текст не поступает
как истина в новый prompt: факты строятся заново по текущим фрагментам снимка.
Файловый список изменений детерминирован, даже если модель не заметила деталь.

## Конкуренция и восстановление

Короткие `BEGIN IMMEDIATE` охраняют claim, проверку лимита, сохранение и
публикацию. MCP/LLM вызовы не держат SQLite lock. Один backend владеет своими
volumes; горизонтальный запуск нескольких backend над одним volume не поддержан.
`Jobs` — локальный ресурсный слот, не durable очередь. Durable intent/состояние
хранится отдельно в таблицах паспорта.

Состояния: CAPTURING, ANALYZING, COMPLETED, NO_CHANGES, BLOCKED, FAILED,
INTERRUPTED. После рестарта незавершённая работа помечается INTERRUPTED.
Если модель могла быть вызвана, тот же fingerprint блокируется до явного
подтверждения. Автоматического fallback/retry и обещания exactly-once для
стороннего API нет. Маркер attempt учитывает возможный расход даже при timeout.

Квота 1–500 попыток за сутки UTC распространяется на ручные и фоновые вызовы,
включая подтверждённый повтор. Историческое usage — реальный ответ API, не
оценка символами. «Пауза» запрещает новые циклы, не отменяет уже отправленный HTTP.
При занятости другого агента scheduler пробует позже без накопления заданий.

## Хранение и API

- GET /api/passport — настройки, текущий паспорт, последние 100 проверок, квота.
- POST /api/passport/settings — явное включение, интервал, provider, лимит.
- POST /api/passport/checks — UUID, retryConfirmed.
- GET /api/passport/checks/{id} — неизменяемый результат завершённой проверки.
- GET /api/passport/checks/{id}/report — Markdown из сохранённых данных без LLM.
- GET /api/passport/checks/{id}/images/{hash} — только media этой проверки.

Проверки и версии не удаляются автоматически; UI ограничивает список последними
100 записями. Снимки, media и SQLite остаются в отдельных Docker volumes дня 35.
Порты 8982/8983/8984 привязаны только к localhost. Игра смонтирована read-only.
GitHub-токен не монтируется, REVIEW_RUNTIME_ENABLED=false. Старые данные дней
32–34 сохранены; их контейнеры остановлены, общий Ollama продолжает работать.
