## Автоматические проверки

- backend: 58, включая 15 SupportAgentTest и ReviewPauseTest;
- support-mcp: 10 файловых тестов и один настоящий MCP HTTP integration test;
- Vue/Vitest: 14; TypeScript и production build успешны.

Платный ReviewLiveTest выключен по умолчанию и пропущен.
XML backend и Support MCP сохранены локально в artifacts/day33-tests,
не входят в Git. Dockerfile запускает тесты при сборке каждого сервиса.

Проверены реальные JSON-файлы, сохранение после открытия нового repository,
идемпотентное создание, конфликт UUID, concurrent create, revision CAS,
запрет второго писателя, повреждённый JSON без сброса, изоляция пользователей.
Протокольный тест использует настоящий MCP SDK и Streamable HTTP сервер:
initialize, tools/list, вызов контекста, отказ для чужого тикета и лишнего аргумента.

В тестах use case покрыты MCP до LLM, источники и usage, продолжение,
несовместимые embeddings, отказ MCP без генерации, ошибочная scope-привязка,
ошибка модели без повторов, обрезанный ответ, неверная ссылка и выдуманный путь.
При потере подтверждения JSON-записи перечитывается revision: завершённый
ответ не затирается ошибкой, незавершённый не остаётся RUNNING при доступном хранилище.
Модель повторно не вызывается. Эти сетевые неопределённости воспроизводились
на тестовых портах, не отключением сети во время настоящего платного запроса.

## Живой прогон через UI

Генерация выполнялась только локальной qwen3:8b: шесть запросов.
DeepSeek дня 33 не вызывался. Embeddings — локальная qwen3-embedding:0.6b.
Индекс FAQ построен кнопкой в UI: четыре документа, 17 фрагментов.

Проверены:

1. Создание обращения Анны с темой, сборкой, платформой и обстоятельствами.
2. Короткий вопрос по тикету без повторного описания: модель получает
   обстоятельства через get_ticket_context и источники сохранений через RAG.
3. Продолжение и новое уточнение. В третьем ходе MCP-контекст содержит
   два предыдущих обмена. Старые модельные ответы не включаются в новый prompt;
   сохраняются только уточнения игрока, полные ответы остаются в JSON для аудита.
4. Профиль Бориса не видит обращения Анны. Прямой HTTP запрос с identity
   Бориса к обращению Анны возвращает 404 TICKET_NOT_FOUND.

   про «Настройки → Тест боссов», с реальной ссылкой на соответствующий фрагмент.
6. Вопрос об облачном аккаунте и кроссплее не получает выдуманной
   инструкции входа или синхронизации. Модель указывает границы знаний.
7. Markdown скачан реальной кнопкой UI; содержит обращение, вопросы,
   ответы, контекст и источники.
8. После пересоздания Support MCP/backend обращения, ответы и индекс сохранились.
   Повтор POST с прежним UUID вернул прежний ход, не добавил сообщение,
   сохранил исходные метрики генерации.
9. На viewport 319 px нет горизонтального переполнения. Панель обращений
   раскрывается, форма и переписка доступны. Ошибок консоли в итоговом UI нет.

## Ошибка локальной модели и выходная политика

Первый диагностический ответ qwen3:8b, до усиления политики, придумал
AppData-путь и не поставил ссылки. Он не удалялся ради демонстрации успеха.
Старый ответ помечается UI как не подтверждённый FAQ.

Добавлены SupportOutputPolicy и непроверенный candidateAnswer:
нет ссылок, неизвестный ID или неподтверждённый абсолютный/AppData-путь
не становятся основной рекомендацией. Черновик сохраняется отдельно,
основной результат UNKNOWN, без автоматического повторного вызова.
Последующие живые ответы содержали существующие ссылки и не придумывали
абсолютный Windows-путь.

IDS_VALID не доказывает семантику каждого шага. Qwen может повторять
избыточные проверки, хотя обстоятельства уже переданы. Профиль и тикет —
заявленные игроком данные, а диагноз остаётся гипотезой без реальных логов.
Качество генерации DeepSeek в дне 33 отдельно не проверено.

## Пауза дня 32 и безопасность

Проверены enabled=false и runtimeEnabled=false. PollState.checkedAt остаётся
null, ручной sync возвращает 409 REVIEW_PAUSED. Unit test подтверждает,
что worker не читает GitHub, не захватывает очередь и не запускает анализ/публикацию.
GitHub workflow игры сохранён, но локальное приложение задания не забирает.

Токены не выводились, не переносились в Support MCP и не передавались в LLM.
JSON-тикеты, SQLite, artifacts, локальные ключи и скачанные отчёты не входят
в кандидаты Git. Проверка паттернов секретов и git diff --check прошли.
Demo identity не заменяет настоящую авторизацию: сервис предназначен для
вымышленных пользователей на loopback, не для публичной поддержки.
