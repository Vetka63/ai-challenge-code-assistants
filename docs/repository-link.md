# Связь репозиториев

## Source control

Игра: https://github.com/Vetka63/ai-challenge-game

Ассистент: https://github.com/Vetka63/ai-challenge-code-assistants

Это два независимых репозитория с собственными `main`, коммитами и PR.
Родительская папка `F:/ai-advent-challenge` не становится Git-репозиторием.
Не добавляем соседнюю папку как вложенный `.git`, submodule или копию кода.

## Локальный доступ

В локальной конфигурации ассистента выбран разрешённый корень игры.
MCP сообщает Git-ветку/коммит этого корня и читает только разрешённые
файлы. GAME_PROJECT_PATH задаёт корень для /help, монтируемый read-only.
Индекс дня 31 использует README/docs. Домен ревью дня 32 получает README/docs
и C# точных версий непосредственно через GitHub API, не из живой рабочей папки.

Переключение ветки игры не должно переключать ветку ассистента. Ассистент
обнаруживает изменение версии источников и предупреждает об устаревшем
индексе вместо молчаливого использования прежних правил.

## PR-пайплайн дня 32

Шаблон integrations/github/ai-review.yml нужно опубликовать в репозитории
игры как .github/workflows/ai-review.yml. Он создаёт JSON-artifact,
локальное приложение забирает задания через GitHub REST API. Код PR
не выполняется на ПК; RAG/анализатор работают в локальном backend.
Токен GitHub и DeepSeek-ключ остаются на ПК. Входящего доступа к ПК нет.
Публикация игры/workflow и создание реальных PR требуют отдельной команды;
наличие шаблона само по себе не означает работающий pipeline.

Для CI не нужны произвольный доступ к домашнему ПК, автоматический
commit исправлений или право merge. Read/review permissions и платные
вызовы выдаются только в рамках согласованного сценария.
