# Проверка поддержки игроков дня 33

UI: http://localhost:8683/#support. Игра не запускается и не изменяется.
День 32 оставлен на паузе. Для видео достаточно UI: контекст, источники
и журнал MCP показаны рядом с каждым ответом.

## Запуск

1. Откройте Docker Desktop.
2. В PowerShell перейдите в F:/ai-advent-challenge/ai-challenge-code-assistants.
3. Запустите powershell.exe -NoProfile -ExecutionPolicy Bypass -File
   scripts/Start-Day33.ps1 -Build.
4. Для существующего DeepSeek-ключа можно дополнительно передать
   -KeyFile F:/ai-advent-challenge/ai-chat/.env -KeyVariable LLM_API_KEY.
   Импортируется только выбранный ключ, не весь чужой env-файл.
5. Откройте UI. Если видите старую страницу, обновите вкладку.

Секреты и JSON-данные не коммитятся. Локальная модель доступна без облачного ключа;
первый ответ может потребовать загрузки весов. Автоматического перехода в облако нет.

## Создать базу знаний

1. Откройте раздел «Поддержка · день 33».
2. На узком экране нажмите «Мои обращения и база знаний».
3. Нажмите «Создать индекс FAQ».
4. Дождитесь «FAQ готов». Индекс поддержки не зависит от старого индекса /help.
   Тикеты и профили в него не включаются.

## Основной сценарий обращения

1. Выберите «Анна · учебный профиль».
2. Нажмите «Создать обращение».
3. Тема: «Не работает Продолжить после переустановки».
4. Сборка: HeroAnimations. Платформа: Windows.
5. Описание: «Сохранил незавершённую экспедицию, затем переустановил игру.
   Теперь Продолжить недоступно. Новую игру не начинал.
   Не знаю, осталась ли папка с сохранениями».
6. Сохраните обращение. Покажите тему и блок «Обстоятельства обращения».
7. Выберите модель. Задайте: «Что проверить в моей ситуации?».
8. Дождитесь ответа. Он должен учитывать переустановку, не считать удаление
   сохранений доказанным и не обещать облачного восстановления.
9. Раскройте «Контекст тикета через MCP»: видны профиль, сборка, платформа
   и исходное описание, хотя в коротком вопросе этих сведений не было.
10. Раскройте «Источники FAQ»: видны реальные фрагменты сохранений/диагностики,
    путь, строки и chunk ID.
11. Раскройте «Журнал MCP»: initialize, tools/list,
    tools/call:get_ticket_context должны иметь SUCCESS.
12. Уточните: «Новую игру точно не запускал. А если файлы всё ещё на диске?».
13. В следующем ответе раскройте контекст: появился предыдущий обмен.
    Обстоятельства не нужно повторять заново. Полная переписка остаётся в JSON,
    в запрос отправляются до трёх последних завершённых обменов.
14. Скачайте MD. В нём есть вопросы, ответы, контекст и источники.
15. Обновите страницу. Переписка должна сохраниться.

## Общий вопрос и разные пользователи

1. Откройте «Вопрос по FAQ».
2. Спросите: «Как сразу потренироваться против босса без длинного забега?».
3. Проверьте ответ по FAQ с источниками; тикетной проблемы здесь нет.
4. Смените профиль на Бориса. Обращений Анны в его списке быть не должно.
5. Если подставить UUID обращения Анны в ссылку Бориса, backend должен
   вернуть «Обращение недоступно», не содержимое чужого тикета.
6. Вернитесь в профиль Анны и откройте прежнее обращение.

Выбор профиля — учебная имитация, не настоящая авторизация.
В работе используются только вымышленные пользователи и обстоятельства.

## Неизвестная функция и сбой

Спросите в FAQ: «Как восстановить облачный аккаунт и включить кроссплей?».
В имеющейся документации нет подтверждения таких функций. Поддержка должна
объяснить границу знаний и уточнить продукт/сборку, а не выдумать инструкцию.

Для проверки restart дождитесь завершённого ответа и выполните docker compose
restart support-mcp backend. После возврата health откройте ту же ссылку:
тикет и ответы должны остаться. Если перезапустить во время генерации,
ход станет INTERRUPTED, без платного автоматического повтора.

Не нажимайте повтор с новым UUID только из-за медленного ответа. При потере
подтверждения UI предлагает «Повторить с тем же ID»: backend вернёт прежний ход.

Если ответ не содержит ссылок или предлагает новый неподтверждённый файловый
путь, появится «Нужны уточнения» и причина UNVERIFIED_ANSWER. Сырой текст
доступен отдельно в «Непроверенном черновике», а не как инструкция игроку.
Это корректный отказ выходной политики, не потеря сообщения. Уточнение
новым вопросом — явный новый вызов выбранной модели.

## Остановка

docker compose stop останавливает приложение с сохранением volumes.
Не используйте down -v, если нужно сохранить обращения и RAG-индексы.
