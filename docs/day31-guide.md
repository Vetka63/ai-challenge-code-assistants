# Запуск и проверка дня 31

## Подготовка Windows

Нужен запущенный Docker Desktop с Linux containers. Для текущего GPU-сценария
используется рабочая NVIDIA/WSL-интеграция. GAME_PROJECT_PATH задаёт корень
игры; по умолчанию это соседний ai-challenge-game. Он доступен только на чтение.

В .env.example указаны параметры. При необходимости создайте локальный .env
с DEEPSEEK_API_KEY. Не показывайте его на видео и не коммитьте.
Без ключа выберите локальную Ollama.

Для импорта ровно одной переменной из существующего локального файла
можно использовать scripts/Start-Day31.ps1 с параметрами KeyFile и
KeyVariable. Остальные настройки/секреты того файла не импортируются.
Например, KeyVariable может быть LLM_API_KEY. Скрипт не печатает ключ.
Обычный docker compose up без локального .env после такого запуска
не подхватит временный ключ; используйте тот же скрипт или свой .env.

Внешний volume OLLAMA_MODELS_VOLUME должен содержать Ollama models:
qwen3-embedding:0.6b и, для LOCAL, qwen3:8b. Текущая машина использует
ai-chat-local-llm_local-models только на чтение. На другой машине задайте
имя своего подготовленного volume. Копировать исходники старого ai-chat не нужно.

## Запуск и остановка

В папке ai-challenge-code-assistants:

    docker compose up -d --build

UI: http://localhost:8683.
API health: http://127.0.0.1:8682/actuator/health.
Project MCP: http://127.0.0.1:8684/mcp — протокол, не HTML-страница.

Остановка с сохранением истории:

    docker compose stop

Не удаляйте volumes. Никакие команды очистки Docker для задания не нужны.

## Сценарий видео

Сохранённый пример уже доступен:
http://localhost:8683/#chat/f8876660-707c-4760-9275-dd9526bbb0c1.
Контрольная серия из шести вопросов:
http://localhost:8683/#chat/063d4f6f-26d4-43fa-853f-11ace471de03.
Это реальные результаты, привязанные к снимкам документации.
Для демонстрации нового запроса выполните шаги ниже.

1. Откройте UI. Если правая панель скрыта, нажмите «Показать контекст».
2. Нажмите ↻: покажите ветку игры, SHA и рабочие изменения.
   Это ветка игры, а не ветка ассистента.
3. Если готового индекса нет, нажмите «Создать индекс README + docs»
   и дождитесь «Готов». Если он уже есть, можно сразу задавать вопросы.
   При изменении игры плашка предупреждает об устаревании, но не блокирует
   ответы. «Обновить индекс» нужно только для получения свежей документации.
4. Раскройте «Документы в индексе»: README, файлы docs, число
   документов/чанков и локальная embedding-модель.
5. Слева нажмите «Новый диалог» (в узком окне сначала откройте ☰).
   Внизу формы сообщения выберите DeepSeek или локальную модель.
6. Отправьте: /help Как устроена связь ECS и Zenject в проекте?
7. Покажите ответ и источники с путями/строками, журнал
   initialize → tools/list → tools/call.
8. Отправьте: /help Как сейчас появляются боссы и чем заканчивается забег?
9. Отправьте: /help Забег уже длится два часа или это только предложение?
   Ожидается различение текущего ActOne на 25–30 минут, прежней 10-минутной
   версии и обсуждения двухчасовой. При обновлении игры ориентир — её новые
   документы, а не старое ожидаемое число.
10. Спросите точную сумму выручки от продаж игры. Ожидается признание
    отсутствия данных, не выдуманное число.
11. Скачайте MD, обновите страницу, откройте тот же диалог:
    история, источники и диагностика должны сохраниться.

Отдельно выберите LOCAL и задайте вопрос для локальной генерации.
Успешное завершение запроса не заменяет проверку смысла ответа.

## Дополнительные проверки

Остановите только project-mcp и отправьте вопрос: ошибка MCP остаётся
в истории. Затем запустите project-mcp обратно. Проверки изменения ветки
и устаревания выполняйте на отдельной fixture-копии, не в живой игре.
Устаревший индекс не является ошибкой: ожидаются ответ по сохранённым
источникам, жёлтое предупреждение и отдельная версия индекса в контексте.
После обновления страницы предупреждение у этого ответа остаётся.
Обновление индекса не меняет задним числом уже сохранённые ответы.

Автотесты:

    .\gradlew.bat :backend:test :project-mcp:test
    cd client
    npm ci
    npm test
    npm run build

Локальный frontend требует Node >=22.12. Docker использует свой Node/Gradle.
Автотесты не обращаются к платным LLM.
