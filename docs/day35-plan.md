# Живой паспорт игры

## Задача и границы

День 35 автоматизирует сбор актуального состояния параллельно разрабатываемой
Unity-игры: обзор, механики, карточки сцен/режимов/запланированных уровней,
изменения, неизвестные сведения и связанные скриншоты. Источник — реальный
разрешённый репозиторий, смонтированный только для чтения. Игра, её Git-ветки,
сохранения и сборки не изменяются; Unity и содержимое проекта не запускаются.

Ветка ai-challenge-day-35 создаётся от сохранённого дня 34 (583018c).
Записанные дни 32–34 остановлены без удаления данных. Незакоммиченный RAG-fix
дня 32 остаётся в своей рабочей копии, не переносится неявно в день 35.

## Согласованный результат

- UI «Паспорт игры»: актуальная версия, карточки уровней, источники и галерея.
- Проверка раз в 600 секунд после предыдущего завершённого цикла.
- Явное включение; режим 30 секунд только с видимой отметкой демонстрации.
- При том же содержимом файлов LLM не вызывается, но факт проверки сохраняется.
- Новая версия паспорта публикуется целиком только после успешной проверки ответа.
- История сохраняет снимок, хеши, фактически переданные источники, usage и ошибки.
- Markdown-экспорт не запускает генерацию. Старые версии не переписываются.

## Доказательства и изображения

Текстовые источники: README, docs, разрешённые C# прототипа и точный
EditorBuildSettings.asset. Наличие сцены в конфигурации сборки не означает
проверенную игровую локацию. Заявленные планы, найденная реализация и сообщения
о прогонах различаются; отчёт о тестах не выдаётся за запуск тестов ассистентом.

Паспорт не восстанавливает текущую истину из предыдущего сгенерированного текста.
Каждый факт связан с заново выбранными фрагментами текущего снимка. Изменения
файлов вычисляются по хешам, включая удаления. Предыдущая успешная версия —
база сравнения, а не незавершённая или ошибочная проверка.

Скриншоты копируются из явно разрешённых растровых файлов проекта, связанных
с документацией, и каталога Assets/Screenshots. Ограничиваются число, байты,
формат и размеры. Проверяются пути, реальные цели и отсутствие symlink.
Снимки хранятся по хешу отдельно от исходников; внешний URL не скачивается.
Дата импорта не считается датой съёмки. Соответствие текущей сборке не обещается
без явного подтверждения источника. SVG, HTML, секреты и произвольные файлы запрещены.
Изображения показываются человеку; LLM получает только метаданные, не пиксели.
Автоматический запуск Unity, vision-анализ и применение diff — вне первой версии.

## Архитектура

Отдельный домен passport внутри backend владеет настройками, проверками,
версиями и указателем последней успешной версии. HTTP и scheduler — тонкие
входные адаптеры одного сценария. Долгие MCP/LLM-вызовы выполняются вне
SQLite-транзакций; захват работы и публикация результата атомарны.

Workspace MCP остаётся владельцем снимков и media. Он собирает неизменяемый
снимок с дедупликацией по содержимому. Backend выбирает ограниченный контекст
и читает реальные диапазоны строк через MCP. Существующие инструменты дня 34
сохраняют контракты; модель не получает произвольный filesystem root или shell.

Provider выбирается явно: LOCAL или DEEPSEEK. Скрытых fallback/retry нет.
Выход — структурированный JSON с обзором, механиками, карточками и вопросами.
Ссылки проверяются по фактически прочитанным источникам; корректный ID не
считается доказательством истинности вывода. Сырой ответ сохраняется для диагностики.

## Планировщик и восстановление

В любой момент одна проверка паспорта; глобальный ресурсный слот согласован
с другими агентами backend. Настройки и ручная кнопка используют ту же логику.
Повтор UUID не создаёт второй вызов. Перекрывающиеся тики не образуют очередь
устаревших снимков. Данные меняются во время чтения — проверка завершается
без модели; новая попытка возможна следующим циклом.

Состояния: CAPTURING → ANALYZING → COMPLETED, либо NO_CHANGES, BLOCKED,
FAILED, INTERRUPTED. Отдельно сохраняются время начала платной попытки и usage.
После рестарта неопределённый вызов не повторяется автоматически.
Та же версия после неудачного модельного вызова блокируется до явного
подтверждённого повтора; прежний успешный паспорт остаётся доступным.
Ограничение расходов в UI действует на ручные и фоновые генерации.
Остановка наблюдения запрещает новые циклы, но не отменяет начатый HTTP-вызов.

## Этапы реализации

1. Сохранить план и правила ветки; не трогать остальные рабочие копии.
2. Сбор и версионирование текстов/скриншотов в Workspace MCP, безопасные media API.
3. Модели паспорта, SQLite-владелец, атомарный жизненный цикл и выбор источников.
4. Генерация с доказательствами, политика ответа, история и MD-экспорт.
5. Планировщик, настройки, ручная проверка и подтверждённый повтор.
6. Vue UI: обзор, карточки, источники, журнал, история и интервалы.
7. Бесплатные тесты путей, снимков, media, конкуренции, отказов и restart.
8. Живой прогон на реальном проекте; отдельная тестовая копия для изменения файлов
   и короткого расписания. Основная игра не изменяется.
9. Гайд для видео и фактический отчёт; commit/push только по отдельной команде.

## Приёмка и видео

Первый паспорт имеет источники и честно различает сцены, режимы и планы.
Повтор без изменений не вызывает модель. Автоматический тик отображается
в журнале и отличается от MANUAL. Контролируемое изменение тестовой копии
создаёт новую версию; удалённый факт не переносится из прежней сводки.
Перезапуск сохраняет историю и настройки. Ошибка не заменяет готовый паспорт.
В UI показываются снимок, охват/пропуски, даты импорта изображений и ограничения.
Для видео можно выбрать видимый интервал 30 секунд; он не выдаётся за 10 минут.
